# Claude 이어하기 안내: CUAI 반도체 박막 MLP 프로젝트

## 이번 작업 목표와 팀 결정

CUAI 학회 발표를 위해 2026년 11월 안에 프로젝트를 마무리한다. 연구 주제는 반사율 스펙트럼에서 다층 박막의 4개 층 두께를 추정하고 입력 잡음에 대한 안정성을 살펴보는 것이다. 최신 사용자 결정은 **전략 1: 팀원 각자가 모델을 구현하고 2026-11-10(화)에 모아 비교한 다음 후속 실험을 정한다**이다. 현재 영우는 비교 후보로 MLP를 직접 익히는 중이다. 기존 문서의 MLP 고정 잡음 평가안과 지금의 모델 구조 비교 계획이 다르면 최신 사용자 결정을 우선한다.

## 영우의 현재 수준과 안내 방식

사용자는 전산과학 수업에서 Python 기초를 배웠고, AI 모델 구조와 특징을 알아가는 단계다. 한 번에 완성된 학습 코드를 던지지 말고 **단계별로** 진행한다. 새로운 함수·라이브러리마다 무엇을 입력받고, 어떤 처리를 하며, 무엇을 돌려주는지 쉬운 말로 설명한다. 오류가 나오면 정확한 원인을 확인하고 한 번에 한 수정씩 안내한다.

## 작업 환경과 폴더

ZIP을 풀면 이 폴더 구조가 나온다.

- 프로젝트 루트: `2026-10_반도체박막AI연구/`
- Python: Windows의 `C:\anaconda\python.exe` (Python 3.14.6)
- 편집기: VS Code
- 데이터: `작업파일/원본데이터/train.csv`, `test.csv`, `sample_submission.csv`
- 실험 코드: `작업파일/01_데이터확인.py`, `02_데이터분할.py`, `03_모델구조.py`

VS Code 터미널은 프로젝트 루트에서 다음처럼 실행한다.

```powershell
C:\anaconda\python.exe -X utf8 ".\작업파일\02_데이터분할.py"
```

pandas, NumPy, scikit-learn, PyTorch가 현재 설치되어 있다. 설치된 PyTorch는 CPU 전용(2.15.0+cpu)이다. 기기에 NVIDIA RTX 3060이 있지만 현재 PyTorch에서는 GPU를 사용할 수 없다. 당장 CPU에서 작은 미니배치 연습을 계속하고, GPU가 필요해지는 시점에 설치 설정을 확인한다.

## 데이터와 코드 상태

`train.csv`는 810,000행×230열이다. `layer_1`~`layer_4`가 정답 두께이고, `0`~`225`가 반사율 입력 226개다. `test.csv`에는 두께 정답이 없고, 제출 양식의 0도 정답이 아니다.

- `01_데이터확인.py`: CSV 앞부분을 읽어 열 구조를 확인한다.
- `02_데이터분할.py`: 전체 CSV를 50,000행씩 읽어 각 묶음에서 10%씩 뽑아 총 81,000개를 만든 뒤 80:10:10으로 나눈다. 입력 X는 학습 분할만 사용해 표준화한다. 이 구조 때문에 실행 때마다 약 2GB CSV를 다시 읽어 시간이 걸린다.
- 주의: 현재 chunk마다 `sample(frac=0.1, random_state=42)`로 같은 난수 시드를 다시 쓴다. 공식 팀 비교용 표본 추출로 바로 확정하지 말고, 전체에서 균일하게 뽑는 재현 가능한 표집 방법과 공통 분할 인덱스를 먼저 검토한다.
- `03_모델구조.py`: MLP 구조를 만들고 임의 입력 5개가 4개 숫자로 변환되는지만 확인한다. 여기의 임의 출력은 학습 결과가 아니다.
- `02_데이터분할.py` 맨 아래에는 MLP, 첫 5개 학습 표본에서 MAE 계산, Adam 한 번 업데이트 코드가 있다. 실행 결과 MAE는 한 번 업데이트 전 134.0211, 후 133.9413이었다. 이는 자동미분·가중치 수정이 작동하는지 본 **원리 확인용**이다. 실제 학습, 일반화 성능, 잡음 안정성 결과로 발표하면 안 된다.
- 매 실행 시 코드가 새 MLP를 만들고 초기화한다. 여러 epoch 학습이나 모델 가중치 저장은 아직 하지 않았다.

## 다음 진행 권장

먼저 영우가 현재 `02_데이터분할.py`의 한 번 업데이트 코드가 무엇을 하는지 이해하도록 안내한 뒤, 실제 학습 단계로 옮긴다. 다음 코드는 별도 `04_모델학습.py`로 만드는 편이 안전하다. 미니배치·epoch 학습, 매 epoch 검증 MAE 계산, 가장 좋은 가중치 저장을 작은 단계로 추가한다. 최종 홀드아웃을 설정 선택에 사용하지 않는다.

팀원 모델 비교 전에는 모두 같은 표본·같은 train/validation/test 인덱스·같은 평가 잡음·같은 지표·같은 학습예산을 쓰는 합의를 권한다. 사용자의 현재 선택은 먼저 구조를 비교하는 것이며, 잡음 증강은 회의 후 팀이 고르면 다음 실험으로 진행한다.

## Claude에게 이어서 요청할 내용

이 안내와 포함된 문서를 읽고 현재 진척을 확인해줘. 나는 MLP 구조를 확인했고 5개 표본으로 Adam 업데이트 한 번을 실행했어. 이 값은 학습 성능이 아니야. 다음 단계는 VS Code에서 실제 MLP를 단계별로 학습하는 것이며, 새 개념과 각 외부 함수를 쉬운 말로 설명하고 매 단계 실행 결과를 확인해줘. 우선 지금 코드가 `sample()`을 chunk마다 같은 seed로 호출하는 점이 공정한 데이터 표집에 적절한지 검토하고, 공식 팀 비교용 데이터 분할을 안전하게 정리한 다음 학습으로 진행해줘.
